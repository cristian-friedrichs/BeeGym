# Knowledge Base Process

A base de conhecimento deve nascer dos tickets recorrentes, nao de suposicoes isoladas.

## Quando criar ou atualizar artigo

- A mesma duvida aparece em tickets recorrentes.
- Um fluxo essencial gera confusao.
- Uma macro precisa explicar mais detalhes.
- Um bug resolvido revela uma orientacao preventiva.
- Onboarding trava repetidamente no mesmo ponto.

## Processo

1. Identificar padrao nos tickets.
2. Agrupar exemplos sem dados reais de clientes.
3. Definir pergunta principal do artigo.
4. Escrever passos curtos e verificaveis.
5. Revisar tom e riscos.
6. Publicar no diretorio `knowledge-base/`.
7. Vincular macro ou resposta inicial ao artigo.

## Regras de conteudo

- Nao usar dados reais de clientes.
- Nao expor prints com dados sensiveis.
- Nao documentar workaround inseguro.
- Nao prometer feature futura.
- Atualizar artigo quando o produto mudar.

## Qualidade minima

- Titulo claro.
- Para quem e.
- Quando usar.
- Passo a passo.
- O que fazer se nao funcionar.
