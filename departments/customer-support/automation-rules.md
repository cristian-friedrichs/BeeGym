# Automation Rules

Automacoes de suporte devem comecar como documentacao e regras operacionais. Nenhuma automacao real deve ser criada nesta etapa.

## Permitidas agora

- Classificacao sugerida de ticket.
- Rascunho de primeira resposta.
- Sugestao de macro.
- Identificacao de ticket recorrente.
- Sugestao de artigo de base de conhecimento.
- Resumo de bug para revisao humana.
- Relatorio semanal manual com metricas agregadas.

## Nao permitidas agora

- Chat externo.
- Resposta automatica sem revisao em casos sensiveis.
- Reembolso automatico.
- Cancelamento automatico.
- Alteracao de plano.
- Acesso ou mutacao em Supabase.
- Integracao com Vercel, billing, producao ou dados reais.
- Criacao automatica de GitHub Issue sem aprovacao do fluxo CTO.

## Futuras automacoes candidatas

- Sugestao automatica de artigos no ticket interno.
- Rotas automaticas por categoria e prioridade.
- Alerta de alta repeticao por modulo.
- Alerta de risco de churn.
- Painel de metricas de suporte.
- Vinculo entre ticket, artigo e issue tecnica.

## Regra de controle humano

Todo caso de cancelamento, reembolso, cobranca sensivel, seguranca, dados, incidente ou cliente irritado deve ter revisao humana antes da resposta final.
