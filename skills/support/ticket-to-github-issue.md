# Ticket para GitHub Issue

## Objetivo

Converter tickets de suporte em issues tecnicas claras quando houver bug provavel, friccao recorrente ou melhoria rastreavel.

## Quando usar

Use quando um ticket precisa de investigacao tecnica, priorizacao de produto ou acompanhamento por CTO/TI.

## Entradas necessárias

- Ticket original ou resumo seguro.
- Impacto relatado.
- Passos para reproduzir quando existirem.
- Evidencias sem dados sensiveis.
- Categoria e prioridade do suporte.

## Processo passo a passo

1. Remova dados sensiveis e informacoes pessoais.
2. Resuma o problema em linguagem tecnica clara.
3. Separe comportamento esperado e observado.
4. Liste passos de reproducao ou lacunas.
5. Defina impacto e severidade sugerida.
6. Inclua criterio de aceite para fechamento.

## Critérios de qualidade A+

- Issue nao expõe cliente ou segredo.
- Problema e reproduzivel ou lacuna esta clara.
- Impacto do suporte e preservado.
- Criterios de aceite sao verificaveis.
- Nao afirma causa nao confirmada.

## O que não pode fazer

- Copiar ticket bruto com dados sensiveis.
- Prometer ao cliente que a issue sera resolvida em prazo especifico.
- Alterar codigo ou abrir PR durante conversao.
- Criar issue para cada duvida simples sem triagem.

## Output esperado

Issue pronta para revisao com titulo, contexto, impacto, comportamento observado, esperado, reproducao, evidencias, criterios e riscos.

## Checklist final

- [ ] Dados sensiveis foram removidos.
- [ ] Impacto foi descrito.
- [ ] Esperado e observado foram separados.
- [ ] Criterios de aceite foram incluidos.
- [ ] Causa nao confirmada foi evitada.
